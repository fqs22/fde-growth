## 1. 产品概述

### 1.1 一句话定位
一套面向移民咨询/知识付费类业务的 **「内容获客 → 私域孵化 → 付费转化」全链路工具平台**，以 AI 生成与数据分析为核心能力。

### 1.2 业务目标
1. 降低小红书内容生产成本（选题→成文时间从半天降至 30 分钟内）。
2. 提升私信→加微→签约的转化率（漏斗各环节可视化、可优化）。
3. 客户资产沉淀：客户画像、跟进记录、知识库全部结构化留存。

### 1.3 目标用户
| 角色 | 说明 |
|---|---|
| 超级个体（主用户） | 本人：内容创作、客户跟进、成交一体化 |
| 顾问/助理（预留） | 后续可分配跟进任务、查看客户档案 |

### 1.4 与岗位 JD 的映射（求职叙事主线）

> ✅ 已验证：以下「JD 要求」为真实 JD 原文（来源：JD 截图原文件，2026-10-24 读取确认）。

| JD 要求（原文） | 本平台对应模块 |
|---|---|
| 负责 AI 系统在知识付费领域的搭建与优化，聚焦家庭教育及商业培训方向 | AI 内容生成、RAG 知识库、AI 诊断建议 |
| 设计并落地 FDE（Funnel–Drip–Engagement）自动化营销模型，提升用户转化与留存 | 漏斗看板（Funnel）、Drip 孵化序列、互动触发（Engagement） |
| 搭建智能化内容分发与用户成长体系，实现课程产品与用户需求的精准匹配 | 选题矩阵、对标拆解、多平台实践库 |
| 协同内容与运营团队，完成从流量获取到付费转化的全链路系统部署 | 模块 A + 模块 B + 数据看板闭环 |

> 任职要求对照（演示时可用）：熟悉 AI 工具与自动化系统搭建（本平台自身即 AI 搭建成果）；精通 FDE 模型逻辑、有落地用户增长案例（§4 B4 漏斗 + Drip 序列 + 演示数据）；独立完成系统架构设计、数据流程配置及多平台工具集成（§2 架构 + §5 多平台导入适配器）。

## 5. 外部平台对接说明（重要约束）

### 5.1 小红书
**账号现状（✅ 已确认 2026-10-24）**：持有 **专业号** + **普通个人号** 两类账号。

| 数据 | 获取方式 | 结论 |
|---|---|---|
| 笔记数据（专业号） | 专业号创作者中心 → 数据中心 → 导出 Excel | **无开放 API**，采用「后台导出 → 平台导入解析」（A3-1）；✅ 专业号前提已具备 |
| 笔记数据（个人号） | App 创作中心查看，导出能力弱 | 以手动录入 / 截图补录为主，P2 可扩展截图 OCR 解析 |
| 广告数据 | 聚光/蒲公英后台 → 报表导出 | 同上（A3-2）；⚠️ 待确认是否投放过广告 |
| 热点/对标数据 | 手动录入；P2 可做浏览器插件半自动采集 | 无公开 API，爬虫有封号风险，**不采用** |
| 私信 | 无法 API 读取 | 转化链路从「加微」起计量 |

> 📌 双账号设计要点：数据模型需支持「账号」维度（专业号/个人号）区分，看板可按账号筛选；
> 个人号因无导出能力，A3-1 解析器需同时支持 Excel 导入与手动表单录入两条通路。

> 设计原则：**导入适配器模式**——所有外部数据统一走「文件导入 → 解析 → 入库」，未来若开放 API 仅需新增适配器，上层功能不变。这是可作为求职亮点的架构决策。

### 5.2 企业微信
**账号现状（✅ 已确认 2026-10-24）**：企业微信**已完成企业验证**。

| 能力 | 可行性 | 说明 |
|---|---|---|
| 外部联系人同步/标签 | ✅ | 企业已验证，可创建自建应用并授权，客户、标签、跟进人可同步 |
| 渠道活码 | ✅ | 归因到笔记/渠道 |
| 自动回复 | ⚠️ 部分 | 欢迎语与关键词回复可配置；主动消息受 API 限制 → 「AI 草稿 + 人工一键发送」 |
| 客户朋友圈 | ✅ 条件具备 | 企业已验证，需在企微后台开通「客户朋友圈」发表权限即可 API 发表；仍建议发布前合规审核（B5-2） |
| 会话存档 | ⚠️ 需付费 | 需单独购买会话存档服务 + 员工同意授权；初期采用手动补录（B1-3） |

### 5.3 LLM

- 所有生成内容过合规检查（A4-3）。

## 6. 非功能需求
1. **合规与安全（P0）**：客户为移民咨询敏感人群，联系方式与评估信息加密存储；遵守 PIPL；不采集小红书站内数据违规爬取。
2. **数据备份**：每日自动备份（云端数据库）。
3. **权限**：初期单用户；预留顾问角色（只见分配客户）。
4. **可用性**：核心看板与客户档案在 AI 服务异常时可降级使用（复用个人站「数据库异常回退静态数据」的架构经验）。
